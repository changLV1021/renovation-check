# 装修验收记录 PWA

> 版本：v2.2 | 更新日期：2026-05-30

---

## 项目概述

装修验收记录 App，用于装修过程中拍照记录遗留问题，待工人修复后逐一验收确认通过，避免遗漏。无后端、无框架，纯前端 PWA。

**URL:** https://changlv1021.github.io/renovation-check/

| 项目 | 方案 |

## 数据模型

每条验收记录：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 自动 | 唯一标识（时间戳 base36 + 随机串） |
| photo | Blob | **是** | 现场照片（IndexedDB 以 Blob 存储，图片压缩后约 200-500KB） |
| description | string | 否 | 问题描述 |
| location | string | 否 | 所在位置（如"主卧""厨房"） |
| severity | string | 否 | 严重程度：轻微 / 一般 / 严重 |
| trade | string | 否 | 工种：水电 / 木工 / 油漆 / 瓦工 / 其他 |
| date | string | 自动 | 记录时间（ISO 8601） |
| status | string | 自动 | 待验收 / 已通过 |
| passedAt | string | 否 | 验收通过时间 |

## 操作交互

### 左滑删除
- 在列表卡片上向左滑动，卡片跟随手指平移
- 滑动超过 40px 松手后自动吸附，露出红色「删除」按钮
- 滑动不足 40px 松手自动回弹
- 点击删除按钮弹出确认框，确认后删除并自动同步
- 点击卡片其他区域或滑动其他卡片自动关闭删除按钮
- 竖滑滚动不受影响（滑动判定优先检测水平/垂直方向）

## 存储策略

```
用户操作 → IndexedDB（主存储，快速读写）
         → [条件] 如果已连接文件系统 → renov8-data.json（同步备份）

启动时 → 从 IndexedDB 加载（默认）
      → [条件] 如果文件系统句柄有效 → 从 JSON 文件加载到 IndexedDB

导入时 → 先清空全部数据，再导入文件中的所有记录（全量替换，保证跨设备一致性）
```

- **IndexedDB**: 所有环境都支持，作为主数据源
- **文件系统存储**: Chrome/Edge 浏览器额外能力，用于跨浏览器共享
- **导出/导入 JSON**: 通用兜底方案，任何浏览器均可使用

## Service Worker 策略

```
版本: renov8-v2
策略:
  - 导航请求（index.html）: Network-First → 在线取最新，离线用缓存
  - 静态资源（manifest、icon）: Cache-First → 先缓存，不回源
  - 安装后: 立即激活（skipWaiting）
  - 激活后: 立即接管页面（clients.claim），清理旧缓存
```

## 部署

部署到 GitHub Pages：

1. 推送到 GitHub 仓库
2. 仓库 Settings → Pages → 选择 main 分支 /root 目录
3. 等待 1-2 分钟 CDN 生效
4. 手机浏览器打开 GitHub Pages URL → 添加到主屏幕

详细步骤见 DEPLOY.md。

## 开发说明

由于是单文件架构（index.html 内联全部 CSS/JS），开发直接在 index.html 中编辑即可。修改后刷新浏览器即时生效。

**注意事项：**
- 修改 sw.js 后需更新缓存版本号（如 renov8-v3），否则浏览器不会更新 SW
- 图片以 Base64 形式存储在 JSON 导出文件和文件系统备份中
- IndexedDB 数据结构变更需要递增 DB_VERSION
- 左滑删除使用 Touch Events API，需在 touchmove 中 preventDefault 避免页面滚动冲突
